# Plan: 월드 1 이동 흐름·간식·삼색이 전투 개선

## Goal

사용자가 2026-10-12 요청한 7가지 수정사항과 후속 간식 코인 잔액 표시·영구 적립을 월드 1 일반 스테이지 1~4와 삼색이 보스전에 적용한다. 짧은 경로에서도 화면과 걸음걸이가 자연스럽고, 진짜 간식을 먼저 경험한 뒤 외형으로 구별할 수 없는 가짜 간식이 나오며, 장애물과 전투 피드백을 식별할 수 있게 한다. 진짜 간식은 획득 즉시 저장해 나중의 상점에서 쓸 보유 잔액으로 쌓고 오른쪽 상단에 표시한다.

이 문서는 계획 수립 뒤 실행 결과까지 갱신했다. T01~T05 구현과 한국어 커밋 완료. 자동21건·타입·lint·빌드·브라우저 통합 검증은 통과했으며, 실제 기기 청음/터치 입력은 미실시로 구분했다. [검증 기록](../test-plans/2026-10-12-world01-gameplay-refinement.md) 참조.

## Decisions

[요청과 구현 기준](../decisions/2026-10-12-world01-gameplay-refinement.md). 사용자가 지정한 필수 행동과 계획자가 정한 초기 튜닝값을 구분했다.

## Planning Baseline Evidence

- 기준 커밋 `aa48a8c`. 현재 소스와 Tiled 파일은 일반 맵 3840px, 총 24개 기믹이다. 2026-10-01의 2560px 단축 계획은 아직 `pending`이다. 사용자의 체감 보고를 존중하되 이 체크아웃에서 이미 단축됐다고 가정하지 않는다.
- `CameraDirector.setSectionMode()`가 구간 변경마다 `startFollow()`를 호출한다. 설치된 Phaser의 `Camera.js`에서 이 함수는 `scrollX/Y`를 즉시 재설정한다. 앞서 설정한 follow offset도 인자를 생략하면 0으로 덮어쓴다. 끊김의 유력한 기여 요인이며 실제 재생 비교로 확인한다.
- `PlayerAnimator`는 4프레임을 고정 10fps로 재생하고 `[99,99,100,104]` 발 위치를 보정한다. 애니메이션 문제의 단일 원인은 아직 확정하지 않았다.
- 가짜 간식은 `getVisualFrame()`이 `revealed`를 무시해 처음부터 변형 프레임을 사용한다. Tiled 일반 맵에는 진짜 간식 코인이 없다.
- `DefenseToolSystem`은 방어마다 `clang`을 발행하지만 `StageScene`은 `AudioManager`를 생성하지 않는다. 사모예드는 3개의 작은 이미지를 플레이어 주변에 즉시 만든다.
- 현재 `StageRuntime.collectCoin`은 시도 코인만 올리고 `complete`가 최초 클리어 때만 bankedCoins를 올린다. `AutoSaveCoordinator`는 coin-changed를 저장하지 않고 `GameShell`의 해당 구독은 runtime만 갱신한다. 기존 `.hud-stats`의 금고 표시는 모바일 보스전에서 숨겨지므로 잔액·저장·화면을 함께 연결해야 한다.
- 읽기 전용 기준 검사 `npm.cmd run world01:maps:check` 통과: 기존 4개 맵, 24개 기믹, 30개 Tiled 객체. 이는 기존 상태 검사이며 새 요구사항 검증은 아니다.

## Execution Order

T01 → T02 → T03 → T04 → T05. 같은 게임 루프를 고치는 한 Phase 안에서 매 Task를 검증하고 커밋한다. 맵 정의와 생성물, 렌더링과 충돌, 이벤트와 소비자를 각각 함께 고쳐 중간 작업도 실행 가능하게 한다. 후속 코인 요청은 T02의 획득 처리와 같은 단위로 반영해 화면만 바뀌고 실제 잔액은 저장되지 않는 중간 상태를 피한다.

## Existing Plans and Precedence

- [짧은 경로 계획](./2026-10-01-world01-compact-scenes.md)의 미완료 T01은 이번 T01/T02가 대체한다. 2560px, 5구간, 체크포인트 ID와 위치 목표를 이어받고, 최종 개수는 24→32 기믹으로 변경한다.
- 같은 이전 계획의 T02 보스 아레나/배경, T03 깃발/출구, T04 픽셀 하트는 미완료 작업으로 보존한다. 이번 7개 요청의 선행 조건으로 삼지 않으며 이번 계획에서 완료 처리하지 않는다. 이전 계획으로 돌아갈 때 24개 기믹·12HP 같은 옛 기대값을 복원하지 않는다.
- [삼색이 전투 계획](./2026-10-01-calico-combat-feedback.md)의 완료 이력은 유지한다. 해당 계획의 12HP와 48×24 생선 뼈 기준만 이번 계획이 갱신한다. 세 궤적·근접 공격·재채기·3하트·방어 3회는 유지한다.
- 컷신 자동 진행 계획은 완료 상태를 보존한다. `current.md`는 이번 T01~T05 완료 후 Active Task 없음으로 정리했으며 이전 포인터와 후속 미완료 작업을 유지한다.

## Completion Conditions

- 네 일반 맵의 정의·물리 경계·Tiled 너비가 2560px이고, 월드 2~5의 길이는 변하지 않는다. 구간 경계를 통과할 때 카메라가 튀지 않고 발과 몸체의 접지가 유지된다.
- 맵별 정적 장애물 6개, 전체 맨홀 2개·가짜 간식 6개·진짜 간식 20개·체크포인트 2개. 가짜 간식은 획득 전 진짜와 같은 외형이고 각 맵의 처음 3개 배치는 진짜다.
- 오른쪽 상단의 간식 코인 잔액은 기존 `bankedCoins`를 사용한다. 진짜 획득당 즉시+1 및 저장, 사망/스테이지 전환/재접속 후 유지, 클리어 중복 합산 없음. 일반맵·보스·클리어 및 모바일에서 보인다. 상점 기능 자체는 이번 범위 밖이다.
- 생선 뼈, 머리 방패, 왼쪽에서 진입하는 5마리, 세 번의 깡 소리가 실제 전투에서 확인된다. 10번째 유효 타격에만 삼색이를 쓰러뜨린다.
- 정지/재개, 사망/체크포인트, 보스 재진입, 컷신 자동 진행, 승리/클리어 이동이 회귀하지 않는다.
- T05의 명령 검증과 데스크톱·모바일 화면·실제 청취 결과를 기록한다. 이미지 자르기를 썼다면 선행 개선 실패 근거와 원본 보존 경로를 기록한다.

## Scope Notes

초기값은 플레이테스트에서 소폭 조정 가능하지만 위장, 선행 진짜 간식, 방어 3회, 여러 마리의 왼쪽 진입, HP 10, 이미지 자르기 최후 원칙은 고정이다. 후속 요청에 따른 코인 정산·저장·오른쪽 상단 잔액 표시를 포함한다. 요청 밖의 새 월드·상점 개방/상품·새 통화·전체 HUD 개편·일반 사운드 재작곡은 추가하지 않는다. Windows PowerShell에서는 실행 정책을 바꾸지 않고 `npm.cmd`/`npx.cmd`를 사용한다.
