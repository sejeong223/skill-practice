# Plan: 짖기 이미지·효과음·일반 구간 사용과 보스 경고

## Goal
보스전에서 짖기의 실제 10초 쿨타임을 왼쪽 아래에 표시한다. 성공한 짖기 3·6·9회에는 강한 화면 흔들림과 사레 경고를, 월드 1 밥그릇 3회 방어로 강아지가 등장하면 밥그릇 경고를 표시한다. 두 경고는 8% 빨간 배경으로 전투를 보이게 한다.

추가 요청: 기존 플레이 코기가 입을 크게 벌려 짖는 이미지 한 장과 알아들을 수 있는 짖기 효과음을 연결한다. 해금한 짖기를 월드 1 재도전·월드 2 등의 일반 장애물 구간에서도 사용하며, 같은 10초 쿨타임을 왼쪽 아래에 표시한다. 이미지 생성·오디오 제작·코드 수정은 실행 단계에서 한다.

## Tasks
1. **T01**: 10초 쿨타임, 플레이 시간 기준 계산, 3회 카운트, 밥그릇 소환 경고 상태, 카메라 흔들림, UI 전달 이벤트와 단위 검증.
2. **T02**: 왼쪽 아래 쿨타임과 중앙 공통 경고 화면, 반응형 표시, 실제 전투·일시정지·재도전 통합 검증.
3. **T03**: 플레이 코기 기반 짖기 PNG 한 장, 짖기 WAV, 성공한 사용에만 이미지·소리 연결, 일반 장애물 구간 및 보스 통합 검증.

## Why this split
같은 짖기 기능이므로 한 Phase를 유지한다. T01은 실제 시간과 상태, T02는 상태를 보여 주는 UI, T03은 이미지·소리와 사용 동작을 완성한다. 이미지 파일만 먼저 커밋해 실제 게임에서 쓰이지 않는 상태를 만들지 않도록 제작과 연결을 한 Task로 묶는다. 일반 구간 HUD는 T01·T02부터 지원하고 T03에서 실제 입력·애니메이션·소리를 함께 확인한다.

## Regression traps
- `GameShell.cooldowns={{}}`와 `SkillSystem.getRuntimeState()`의 빈 `cooldownUntil`을 실제 데이터로 착각하지 않는다. `getRemainingCooldown()` 값을 새 이벤트로 전달한다.
- 모바일 보스 HUD의 `.hud-stats`는 숨겨진다. 새 쿨타임은 해당 영역 밖 독립 컴포넌트로 둔다.
- 짖기 사용 성공과 보스 경직 성공은 다르다. 범위 밖 짖기도 쿨타임과 사용 횟수를 소비한다.
- 방어 3회 자체를 새로 세지 않는다. 이미 있는 강아지 소환 이벤트를 이용해 소환 중복을 막는다.
- 기존 사망·승리·스킵·월드 선택 저장 정책과 사용자가 복원한 음악은 이번 작업 대상이 아니다.
- `corgi-bark`는 현재 없는 32×48 선택 에셋이다. 실제 플레이 프레임은 112×128이므로 새 단일 이미지도 112×128, 발 기준 99px로 맞춘다.
- PlayerController가 매 프레임 상태를 run/idle 등으로 덮어쓴다. 짖기 표시는 별도 450ms 타이머로 유지해야 한다.
- 현재 효과음은 `bite-hit`에만 연결되어 있다. 짖기 성공 이벤트 `skill-used`를 구독해 입력 실패·쿨타임 중 소리가 나지 않도록 한다.

## Follow-up findings
`SkillSystem.getRuntimeState()`가 항상 빈 쿨타임 객체를 반환하는 기존 미완성 API가 있다. 이번 기능은 정상 동작하는 `getRemainingCooldown()`으로 연결한다. 기존 상단의 빈 쿨타임 행은 공통 왼쪽 아래 짖기 표시와 중복되므로 제거한다. 전체 스킬 상태 API 개편, 아직 해금되지 않는 후속 네 스킬의 전투 구현, 일반 적을 짖기로 경직시키는 새 규칙은 별도 요청이 있을 때 정한다.
