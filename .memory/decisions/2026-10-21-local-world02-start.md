# Decisions: 로컬 개발 실행의 월드 2 시작

- Date: 2026-10-21 (Asia/Seoul)
- Status: 사용자 요청에 따른 작업 기준

## D01. 적용 범위

- **사용자 요청**: 월드 1 수동 테스트가 끝났으므로 지금 로컬에서 게임을 실행하면 월드 2부터 진행한다.
- **작업 가정**: `npm run dev`의 개발 모드에서 브라우저 저장 상태가 월드 1을 가리켜도 월드 2의 첫 스테이지를 시작한다. `next build`로 만든 배포 실행에서는 기존 시작·복원 로직을 유지한다. 저장 데이터는 삭제하지 않는다.
- **이유**: `src/app/page.tsx`의 `initialStageId`는 HUD 초기값일 뿐이며 실제 장면은 `PreloadScene.create`가 저장 상태를 읽어 결정한다. 시작점만 바꾸면 사용자가 보는 장면은 바뀌지 않을 수 있다.

## D02. 인트로와 개발 진행 상태

- **기존 흐름에서 확정**: 월드 2 인트로를 아직 보지 않았다면 기존 `World02EntranceScene`을 거쳐 첫 스테이지로 간다. 이미 본 경우 첫 스테이지로 바로 간다. 월드 1 인트로와 이름 입력 화면은 개발 모드 시작에서 건너뛴다.
- **기존 코드 제약**: `GameShell`은 `onboardingCompleted`가 거짓이면 게임 HUD 대신 인트로/이름 화면을 보여 준다. 월드 선택 버튼은 `clearedStages`에 `world-01-stage-boss`가 있어야 열린다. 개발 시작 상태에는 이 완료 표시와 짖기 스킬을 보충하고 `selectedWorldId`를 `world-02`로 맞춘다. 코인·장비·꾸미기·사망 기록 등 기존 값은 유지한다.
- **저장에 미치는 영향**: 자동 저장은 변경된 개발 시작 상태를 브라우저 저장소에 기록할 수 있다. 기존 값을 삭제하거나 초기화하지 않지만, 월드 1 보스 완료·짖기 해금·선택 월드는 개발 시작 기준으로 갱신될 수 있다.

## D03. 범위 밖

- 월드 2의 후속 스테이지 구성과 진행 난이도, 월드 1의 수동 테스트 결과, 리셋 버튼의 의미, 저장 스키마는 바꾸지 않는다.
