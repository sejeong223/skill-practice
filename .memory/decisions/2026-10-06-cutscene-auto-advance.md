# Decisions: 컷신 대사 자동 진행

- Date: 2026-10-06
- Status: Confirmed
- Scope: 오프닝, 월드/보스, 엔딩 컷신의 나레이션과 대사. 장면의 배우·카메라 동작과 대본 순서는 유지한다.

## D01. 자동 진행 범위

- **Chosen (User)**: 오프닝을 포함해 화면에 나오는 모든 컷신 대사는 Enter 없이 다음 문장과 장면으로 자동 진행한다.
- **Codebase finding**: `IntroScene`은 문장마다 `advance()` 입력을 기다리고, `CutsceneDirector`는 월드 1 보스 등장·승리 컷신만 타이머를 끈다. 다른 월드/엔딩 컷신은 이미 `CutsceneTimeline` 타이머를 사용한다.
- **Rationale**: 두 수동 대기 경로를 없애야 첫 재생부터 모든 대사가 끝까지 진행된다.

## D02. 재생 시간

- **Chosen (User)**: 각 문장 길이에 맞는 읽을 시간을 확보한다. 기존 인트로 목표인 35~40초보다 길어져도 된다.
- **Chosen (Implementation)**: `beat.durationMs`는 연출의 최소 시간으로 유지한다. 화면에 동시에 나타나는 문구의 글자 수로 더 긴 표시 시간이 필요하면 그 시간을 사용한다. 글자 출력은 해당 시간의 80% 안에 끝나고 나머지 시간은 전체 문장을 보여준다.
- **Rationale**: 현재 긴 나레이션이 2~4초에 사라지지 않게 하면서 짧은 대사와 텍스트 없는 장면의 기존 연출 시간은 지킨다.

## D03. 기존 입력과 선택 단계

- **Chosen (Inferred from request and existing decisions)**: 클릭·Space·Enter로 문장을 빨리 공개하거나 다음 문장으로 넘기는 기존 조작과 재시청 시의 건너뛰기는 계속 제공한다. 입력하지 않아도 타이머가 같은 경로를 호출한다.
- **Boundary**: 인트로 뒤 타이틀/이름 입력과 월드 1 보스 승리 뒤 `[STAGE CLEAR!]`의 `NEXT STAGE ->` 버튼은 대사가 아닌 선택 단계다. 이들은 기존 사용자 결정을 따라 입력을 기다린다.
- **Rationale**: 새 요구는 대사의 자동 진행이며 이름과 다음 스테이지를 정하는 선택까지 자동 확정하는 요구는 아니다.

## D04. 생명주기와 검증

- **Chosen (Implementation)**: 문장별 타이머를 수동 넘김·건너뛰기·컷신 종료·씬 종료 시 정리하고, 한 비트의 배우·카메라 동작은 문장이 여러 개여도 한 번만 실행한다. 자동 진행과 선택적 수동 진행 모두 마지막 컷신 종료 이벤트를 한 번만 낸다.
- **Validation**: 시간 계산과 공용 컷신 타임라인을 자동화 테스트로 검증하고, 오프닝 전체·월드 1 보스 등장/승리·이름 입력·스테이지 클리어 경계는 실제 화면에서 확인한다.
