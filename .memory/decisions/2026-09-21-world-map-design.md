# Decisions: 5개 월드 맵 디자인

- Date: 2026-09-21
- Status: Confirmed
- Scope: 5개 월드의 시각 테마, 스테이지 구조, 맵 제작 방식, 억까 기믹 배치와 런타임 규칙

## D01. 월드 구성

- **Chosen**: 월드 5개, 월드마다 일반 스테이지 4개와 보스 스테이지 1개
- **World 1**: 뒷골목
- **World 2**: 놀이터
- **World 3**: 뒷산
- **World 4**: 냥아치 아지트
- **World 5**: 캣타워 공성전
- **Rationale**: 선형 캠페인 구조와 기존 25개 스테이지 규모를 유지하면서 장소별 개성을 명확히 한다.

## D02. 일반 스테이지의 기본 구조

- **Chosen**: 모든 일반 스테이지는 좌우 가로 진행의 5개 구간으로 구성한다.
- **Section layout**: 짧은 진입 구간 → 억까 구간 1 → 억까 구간 2 → 억까 구간 3 → 짧은 탈출 구간
- **Safe sections**: 진입·탈출 구간은 각각 전체 길이의 약 5%로 한다.
- **Safe rule**: 진입·탈출 구간에는 즉사, 강제 이동, 퇴로 봉쇄를 배치하지 않는다.
- **Rationale**: 장소를 인지할 최소한의 여유만 주고 스테이지 대부분을 고밀도 억까 구간으로 사용한다.

## D03. 스테이지 길이와 카메라 영역

- **Chosen**: 일반 스테이지 길이는 3,840px, 기본 플레이 높이는 720px으로 한다.
- **Vertical exception**: 수직 세트피스가 있는 맵은 최대 1,152px 높이를 사용할 수 있으며, 해당 구간에서만 상하 카메라 추적을 활성화한다.
- **Chosen**: 보스 아레나는 약 1,920px 규모의 전용 맵으로 만든다.
- **Rationale**: 모든 일반 스테이지의 길이를 일정하게 유지해 난이도와 플레이 시간을 비교하기 쉽게 한다.

## D04. 맵 제작 파이프라인

- **Chosen**: Tiled와 TypeScript를 결합한 하이브리드 방식
- **Tiled responsibility**: 타일, 발판, 벽, 정적 장식, 배경 레이어, 오브젝트 위치
- **TypeScript responsibility**: 함정 동작, 적 행동, 랜덤 변형, 연쇄 반응, 카메라 이벤트, 체크포인트 상태
- **Rationale**: 시각적 맵 배치는 에디터에서 정교하게 관리하고, 복잡한 억까 로직은 코드에서 재사용한다.

## D05. 타일·맵 파일 구조

- **Chosen**: 16×16px 기본 타일
- **Chosen**: 월드별 공용 타일셋 1개와 스테이지별 맵 파일을 사용한다.
- **Expected assets**: 월드 5개 타일셋, 25개 스테이지 맵 파일
- **Rationale**: 32×48px 코기 스프라이트에 맞춰 세밀한 발판과 함정 배치를 가능하게 하면서 월드별 시각적 통일성을 유지한다.

## D06. 스테이지별 장소 구성

- **Chosen**: 각 월드는 4개의 하위 장소와 1개의 보스 장소로 구분한다.
- **World 1 draft**: 무법지대 뒷골목 → 빨래방 지붕길 → 도둑고양이 지름길 → 담벼락 추격전 → 냥아치 초소
- **World 2 draft**: 그네 광장 → 놀이기구 구역 → 정글짐 미로 → 놀이터 뒤편 → 놀이터 관리실
- **World 3 draft**: 산길 입구 → 숲속 오솔길 → 절벽 등산로 → 동굴 지름길 → 산 정상
- **World 4 draft**: 고물상 외곽 → 폐차 처리장 → 냥아치 작업장 → 아지트 내부 → 간부실
- **World 5 draft**: 캣타워 외벽 → 하층 방어선 → 중층 공성 구역 → 상층 회랑 → 우두머리의 옥좌
- **Rationale**: 공용 타일셋을 사용하되 스테이지마다 랜드마크, 조명, 장식, 지형을 달리해 장소 전환을 느끼게 한다.

## D07. 월드별 시각 테마

- **Chosen**: 월드마다 강하게 대비되는 색감과 조명을 사용한다.
- **World 1**: 화창한 낮의 푸른 하늘, 중립적인 주거지 색감과 선명한 햇빛
- **World 2**: 밝은 놀이공원 계열 색감과 보라색 불안 요소
- **World 3**: 자연 녹색·갈색과 바위·흙 재질
- **World 4**: 고철의 회색·주황 경고등과 어두운 작업장 조명
- **World 5**: 검정·짙은 보라색 본부와 금색 캣타워 왕좌
- **Rationale**: 월드 진입 순간 색과 재질만으로 장소를 식별하게 한다.

## D08. 배경 레이어와 전경 가림

- **Chosen**: 먼 배경, 중경, 플레이 레이어, 전경의 4단계 패럴랙스를 사용한다.
- **Chosen**: 전경 장식은 적극적으로 플레이어와 함정을 가릴 수 있다.
- **Constraint**: 가림 효과와 충돌 판정은 분리한다. 실제 충돌은 렌더링 가림 여부와 관계없이 일관되게 동작한다.

## D09. 월드별 억까 기믹 규모

- **Chosen**: 월드마다 핵심 기믹 6종과 기믹별 3~5개 변형을 확보한다.
- **Expected volume**: 월드당 약 18~30개 패턴
- **Pattern rule**: 같은 외형의 사물도 스테이지, 위치, 상황에 따라 안전한 발판·함정·적 호출 장치·이동 장치로 다르게 동작할 수 있다.
- **Rationale**: 단순히 함정 수만 늘리지 않고 동일한 사물을 재해석해 각 월드의 억까 밀도를 확보한다.

## D10. 월드별 핵심 기믹 방향

- **World 1 뒷골목**: 맨홀, 쓰레기통, 빨랫줄, 에어컨 실외기, 울타리, 고양이 미끼 등 주거지 사물의 배신
- **World 2 놀이터**: 그네, 미끄럼틀, 시소, 모래밭, 정글짐, 스프링 놀이기구의 오작동과 방향 반전
- **World 3 뒷산**: 굴러오는 돌, 부러지는 나뭇가지, 기울어지는 통나무, 풀숲, 무너지는 흙길, 동물의 연쇄 작동
- **World 4 냥아치 아지트**: 폐차, 고철 더미, 자석 크레인, 가짜 문, 감시 카메라, 압축기와 경보 장치
- **World 5 캣타워 공성전**: 회전 발판, 층별 방어선, 고양이 장난감 발사기, 밥그릇 경보, 이전 월드 기믹의 냥아치식 개조
- **Reuse rule**: 다음 월드에서 이전 월드 기믹을 일부 변형 재사용하고, 월드 5에서 1~4월드의 핵심 기믹을 적극적으로 종합한다.

## D11. 기믹 배분과 억까 밀도

- **Chosen**: 월드의 4개 일반 스테이지에 기믹을 단계적으로 누적한다.
- **Stage 1**: 새 사물과 함정의 첫 변형 소개
- **Stage 2**: 기존 기믹의 변형과 2개 시스템 조합
- **Stage 3**: 화면 밖 공격, 랜덤 변형, 복합 연쇄 강화
- **Stage 4**: 해당 월드의 억까를 보스 직전 수준으로 종합
- **Exception**: 진입·탈출 5% 안전 구간을 제외한 중앙 구간은 억까 밀도를 낮추지 않는다.

## D12. 함정 동작과 랜덤성

- **Chosen**: 고정 함정 중심에 반응형·이동형·랜덤 함정을 혼합한다.
- **Chosen**: 스테이지 시작 시 랜덤 시드를 정하고 한 번의 도전 동안 유지한다.
- **Chosen**: 체크포인트에서 재시작할 때는 같은 시드를 유지하며, 스테이지를 처음부터 재시작할 때 새 시드를 적용한다.
- **Rationale**: 한 번의 시도에서는 패턴을 학습할 수 있지만, 완전 재시작 때마다 작은 변수가 생긴다.

## D13. 연쇄 반응 규칙

- **Chosen**: 데이터 기반 `조건 → 반응` 규칙으로 정의한다.
- **Tiled properties**: `trapId`, `variant`, `chainId`, `seedGroup` 등을 오브젝트 속성으로 기록한다.
- **Examples**: 밥그릇 공격 방어 → 전투 중 소리 발생 → 유기견 출현, 짖기 → 간판 반응 → 고양이 출현, 상자 파괴 → 뒤쪽 적 매복
- **Rationale**: 동일한 오브젝트를 스테이지마다 다른 억까 조합으로 재사용할 수 있다.

## D14. 체크포인트와 사망 후 복구

- **Chosen**: 일반 스테이지당 체크포인트 1개
- **Placement**: 3구간과 4구간 사이
- **Chosen**: 사망 시 마지막 체크포인트의 맵 상태로 완전 복구한다.
- **Reset targets**: 움직인 고철, 닫힌 문, 소환된 NPC, 작동한 함정, 동적 오브젝트
- **Rationale**: 체크포인트는 진행 위치만 저장하는 것이 아니라 해당 도전의 학습 가능한 상태를 복구한다.

## D15. 카메라

- **Chosen**: 코기를 화면 중앙이 아닌 왼쪽 25% 지점에 둔다.
- **Horizontal behavior**: 부드러운 횡스크롤과 전방 우선 시야
- **Vertical behavior**: 수직 구간에서만 부드러운 상하 추적을 활성화한다.
- **Camera effects**: 대형 함정, 보스 등장, 환경 붕괴 등 특정 순간에만 짧은 흔들림·줌·팬을 사용한다.
- **Rationale**: 전방 맵을 최대한 넓게 보여주면서도 연출용 카메라 효과로 충격감을 만든다.

## D16. 진행 방향과 선택 루트

- **Chosen**: 기본은 좌→우 단방향 진행이다.
- **Backtracking**: 수집품을 위한 선택형 위험 루트에서만 짧은 되돌아가기를 허용한다.
- **Rationale**: 선형 캠페인 구조를 유지하고, 뒤에서 재등장하는 함정과 적의 관리 부담을 줄인다.

## D17. 스킬·도구와 맵의 경계

- **Chosen**: 스킬은 전투와 보스전에만 사용한다.
- **Constraint**: 맵 진행을 위해 특정 스킬을 요구하지 않으며, 스킬로 필수 발판·문·출구를 열지 않는다.
- **Chosen**: 공격·방어 도구는 맵 이동용으로 사용하지 않는다.
- **Constraint**: 도구가 맵 지형이나 필수 이동 경로를 변경하지 않도록 한다. 도구의 억까 부작용은 전투 상황 안에서 처리한다.

## D18. 보스 아레나

- **Chosen**: 보스마다 약 1,920px 전용 아레나를 사용한다.
- **Structure**: 공통 진입·전투·마무리 3구역 골격 + 보스별 전용 지형과 환경 기믹
- **Final boss**: 캣타워 최상층 우두머리의 옥좌에서 왕갈비뼈는 배경에 보이기만 하며 전투 도구로 사용하지 않는다.

## D19. 환경 애니메이션과 성능 경계

- **Chosen**: 배경은 상시 애니메이션을 사용하고, 일부 환경 오브젝트는 실제 함정·연쇄 이벤트와 연결한다.
- **Rule**: 장식 애니메이션과 충돌·함정 애니메이션을 별도 시스템으로 관리한다.
- **Rationale**: 월드의 생동감은 높이되 모든 장식을 물리 오브젝트로 만들어 검증 복잡도를 폭발시키지 않는다.

## D20. 에셋 제작 방식

- **Chosen**: 월드별 콘셉트 시트에서 16×16px 타일셋 시트와 큰 상호작용 오브젝트 시트로 확장한다.
- **Pipeline**: 생성형 이미지로 기준 디자인 제작 → 픽셀 스타일·팔레트 정리 → 타일 경계 및 반복성 정리 → Phaser 프레임·충돌 영역 검수
- **Rationale**: 사용자가 직접 그리지 않아도 코기·고양이와 같은 픽셀 스타일을 월드 맵 전체에 유지한다.

## D21. 검증

- **Chosen**: 자동 검증과 수동 플레이테스트를 함께 수행한다.
- **Automated checks**: 시작점·체크포인트·출구 연결, 필수 발판 누락, 충돌 영역, 출구 도달 가능성, 오브젝트 체인 참조
- **Manual checks**: 실제 조작감, 카메라 가림, 억까 타이밍, 랜덤 시드별 클리어 경로, 스킬·장비 경계
- **Quality bar**: 첫 시도에는 거의 피하기 어려운 함정을 허용하되, 패턴을 파악하면 최소 하나의 클리어 경로가 존재해야 한다.
