# Decisions: 코기 발레 피루엣 점프

- Date: 2026-10-28
- Status: Confirmed
- Scope: 점프 전신 디자인과 애니메이션의 설계 결정. 이 문서에서는 구현 코드를 수정하지 않는다.

## D01. 회전축과 전신 이미지

- **Chosen (user)**: 코기가 두 뒷발로 일어서는 발레 자세를 취하고, 세로축을 중심으로 한 바퀴 돈다. 회전 중 옆모습뿐 아니라 정면과 뒷모습을 거쳐 원래 옆모습으로 돌아온다.
- **Rationale**: 현재 게임이 옆모습 2D이므로 회전 각도별 전신 프레임이 있어야 피루엣으로 보인다. 기존 가로 코기 이미지를 회전시키거나 얼굴만 덧대는 방식은 요구한 자세를 표현하지 못한다.

## D02. 의상과 코기 디자인

- **Chosen (user)**: 점프할 때 별도의 튀튀나 발레슈즈를 입히지 않는다. 현재 착용한 의상을 유지하고 코기의 전신 자세와 회전만 바꾼다.
- **Derived from prior user feedback**: 기존 코기의 주황색·흰색 무늬, 얼굴 비율, 픽셀 윤곽과 안광 없는 눈을 기준으로 각 방향의 몸통·다리·앞발·얼굴을 새로 그린다. 기존 가로 몸통 또는 얼굴 이미지를 그대로 붙여서 전신처럼 보이게 하지 않는다.
- **Derived from code**: 기본 코기 외에 의상 5종, 사용자가 색칠하는 의상 템플릿, 별도 장신구 레이어가 있다. 회전 프레임에서도 실제 착용 모습과 장신구 위치가 맞아야 한다.
- **Rationale**: 사용자가 선택한 기존 의상을 점프 때도 알아볼 수 있어야 하며, 정면·뒷모습은 기존 옆모습 이미지의 단순 좌우 반전으로 만들 수 없다.

## D03. 적용 대상

- **Chosen (user)**: 일반 점프와 더블 점프 각각이 시작될 때 한 바퀴 회전을 시작한다. 공중에서 두 번째 점프를 하면 새 회전을 시작한다.
- **Derived from request and code**: 단순 낙하나 발판에서 걸어 떨어지는 경우는 점프 시작이 아니므로 회전을 새로 시작하지 않는다. 점프 속도, 중력, 공중 이동, 충돌 판정은 기존 규칙을 유지한다.
- **Rationale**: 회전은 실제 점프 동작에 대응하고 물리 규칙을 바꾸지 않는다.

## D04. 회전 길이와 착지

- **Chosen (user)**: 이륙 후 약 0.6초 동안 한 바퀴 돌고, 여전히 공중에 있으면 끝난 발레 자세를 유지한다. 착지하면 평소 달리기·대기 자세로 복귀한다.
- **Derived from code**: 일반 점프의 기본 속도는 `-460px/s`, 중력은 `1200px/s²`로 같은 높이 착지까지 공중 체류가 약 0.77초다. 조기 착지, 천장 충돌, 사망 또는 위치 초기화 시에는 공중 연출 상태를 정리한다.
- **Rationale**: 고정된 회전 속도를 유지하면서 긴 낙하 중에 불필요하게 계속 돌지 않게 한다.

## D05. 발레 자세의 기준

- **Chosen (user)**: 첨부된 강아지 사진처럼 한쪽 뒷발을 축으로 서고, 다른 뒷발을 옆으로 뻗으며, 두 앞발을 펼친다.
- **Rationale**: 수직으로 선 코기와 네 발 모두의 위치가 읽혀야 첨부 이미지의 발레 자세가 전달된다.

## D06. 공중 스킬과 점프 연출

- **Chosen (user)**: 점프 도중 짖기나 물기를 써도 화면에는 발레 회전 이미지를 끝까지 우선 표시한다.
- **Derived from code**: `StageScene`에서 두 스킬은 공중 사용을 막지 않으며 실제 스킬 판정은 애니메이션 표시와 별개다. 피해·경직·재사용 대기시간 등 기존 효과는 그대로 적용하고 시각적 자세만 점프가 우선한다.
- **Rationale**: 스킬 사용 때문에 한 바퀴 회전이 중간에 끊겨 보이지 않게 한다.

## D07. 공중 방향 전환

- **Chosen (user)**: 이륙할 때의 시각적 방향을 착지할 때까지 유지한다. 공중에서 좌우 이동 방향을 바꿔도 회전 그림은 즉시 반전하지 않는다.
- **Derived from code**: `PlayerController`는 입력에 따라 `flipX`를 갱신하므로, 회전 중 표시 방향은 이동 방향과 별도로 관리해야 한다.
- **Rationale**: 회전 도중 프레임이 갑자기 반대로 뒤집히는 현상을 방지하면서 공중 이동 조작은 유지한다.

## 구현 계획에서 확인할 코드 제약

- `PlayerAnimator`는 현재 `jump`·`fall` 상태에서도 달리기 이미지를 멈춰 보여준다. 전신 회전 프레임의 재생 시작·완료·착지 복귀를 연결해야 한다.
- `PlayerAppearanceTextures`와 `PlayerWearables`는 현재 `run`·`bark`·`bite`만 다룬다. 기본 코기, 의상 5종, 색칠 의상 템플릿 및 장신구가 새 회전 자세를 지원하도록 자산 계약과 동기화를 설계해야 한다.
- `Player`의 물리 몸체는 `72×40`이며 발 위치를 이미지 프레임 앵커에 맞춘다. 서 있는 프레임의 높이와 발 앵커를 검토하되 충돌 몸체의 게임플레이 크기는 유지한다.
- `assetManifest.json`에 예전 `corgi-jump`·`corgi-double-jump` 항목이 있지만 해당 PNG는 없고 현재 프레임 규격도 실제 코기 이미지와 다르다. 새 전신 회전 자산에 맞는 로드 규격을 정해야 한다.

## 인터뷰 중 확인한 인접 사항

- `SKILL_DEFINITIONS`에는 더블 점프가 정의되어 있으나 현재 `StageScene`에서는 해당 스킬을 사용하지 않는다. 이 결정은 더블 점프가 실제 발생할 때의 회전 모습을 정한 것으로, 더블 점프 기능 자체의 신규 구현은 요청 범위에 넣지 않았다.
