# Decisions: 월드 1 플레이 흐름·간식·보스 피드백

- Date: 2026-10-12 (Asia/Seoul)
- Source: 사용자의 7개 수정 요청 및 후속 간식 코인 잔액·상점 대비 적립 요청, 기존 2026-10-01/2026-09-29 결정, 현재 체크아웃 조사
- Status: 사용자 요구사항을 계획에 반영. 아래 초기 튜닝값은 계획자의 구현 기본값이며 별도 인터뷰에서 확정받았다는 뜻이 아니다.
- Scope: 월드 1 일반 맵 1~4와 삼색이 전투

## D01. 짧은 맵의 자연스러운 이동

기존 목표인 2560px를 유지하되 현재 코드가 아직 3840px인 점을 먼저 정합화한다. 카메라의 구간별 `startFollow` 재호출과 offset 소실을 고치고, 발 접지와 속도 대비 애니메이션 주기를 확인한다. 맵 크기에 맞춘 원근 레이어 표시 영역·텍스처 스케일·반복 이음새 개선이 다음 순서다. 이 방법들로 해결되지 않는 이미지 자체 문제를 재현한 경우에만 원본을 보존한 별도 파생 이미지 자르기를 사용한다. 원본을 먼저 자르거나, 이동/중력 값을 임의로 바꿔 시각 문제를 덮지 않는다.

## D02. 간식 위장과 순서

초록 사망 코인은 접촉 이전에 진짜 간식과 같은 프레임·크기·높이·색·움직임을 사용한다. 기존 역주행/발사 가짜 간식도 같은 공통 미발동 표현으로 정렬한다. 효과의 종류는 수집 이후에만 드러난다. 각 맵 초반 x224/304/384에 진짜 3개를 놓고, 이후 진짜를 더 섞어 가짜가 뒤에 나오게 한다. 정상 진행 시 세 번의 실제 획득을 먼저 경험하도록 걷는 높이에 배치한다. 플레이어가 일부러 뛰어넘은 간식을 강제로 먹이거나, 획득 횟수에 따라 가짜를 순간 생성하는 규칙은 추가하지 않는다.

## D03. 장애물과 비둘기

초기 목표는 각 맵 정적 장애물 4→6개, 스테이지 2/4 열린 맨홀 각 1개 유지다. 전체 기믹은 정적 24+맨홀 2+가짜 간식 6=32개가 된다. 진짜 간식은 맵별 5개·총 20개이며 치명적 기믹 수에 포함하지 않는다. 비둘기 표시를 60×40으로 키우고 몸통 안쪽 충돌 범위도 함께 조정한다. 시작·출구·체크포인트의 안전한 발판을 보존한다.

## D04. 생선 뼈와 머리 방패

생선 뼈 초기 표시 목표는 72×36, 충돌 영역은 54×24다. 세 가지 투척 궤적·700ms 예고·2600ms 간격은 유지한다. 밥그릇은 코기 머리를 따라가는 별도 투명 레이어로 먼저 구현해 기존 걷기 프레임을 보존한다. 현재 `upside-down-bowl` 키는 여러 아이템이 함께 있는 불투명 레퍼런스이므로 그대로 머리에 올리지 않는다. 독립 투명 밥그릇을 준비하고, 결합이 계속 어색하면 기존 코기를 참조한 밥그릇 착용 시트 생성도 허용한다. 세 번째 방어까지 타격 반응을 보인 뒤 방패가 사라진다.

## D05. 사모예드 무리

세 번째 방어에서만 시작한다. 초기값 5마리가 보이는 화면 왼쪽 밖에서 오른쪽으로 달려와 코기를 앞에서 가린다. 시작부터 코기 주변에 나타나거나 반투명해지는 표현으로 대체하지 않는다. 기본 입장 650ms+개체당 70ms 시차, 방어 시점부터 2200ms의 기존 제어 잠금 뒤 해제, 300ms 퇴장을 사용한다. 입장 중에도 기존 불이익 규칙은 유지하되 죽음/승리/재시작 시 즉시 정리한다. 다른 월드/프로토타입의 개 이벤트 기본값은 바꾸지 않는다.

## D06. 깡 소리

`DefenseToolSystem`의 기존 `clang` 이벤트를 유일한 방어음 트리거로 사용한다. 실제 스테이지에 `AudioManager`를 연결하고 짧은 금속성 감쇠음을 만든다. 세 번 각각 1회, 과도한 고음이나 큰 소리는 피한다. 세 번째에 무리 소리가 깡 소리를 덮지 않게 짧게 늦춘다. 브라우저 음원 잠금은 정상 입력으로 풀고, 재진입 시 중복 구독/잔향/예약음을 남기지 않는다.

## D07. 보스 HP

삼색이 최대 HP는 정확히 10. 초기값·재시도·10칸 게이지·`현재 / 10` 표기를 동일한 상수로 묶는다. 근접 공격 1회당 1피해, 유효 타격 10번째 승리, 코기 3하트와 방패 3회는 유지한다.

## D08. 오른쪽 상단 보유 간식 코인과 영구 적립

- **User requirement**: 나중에 상점에서 쓸 간식 코인을 계속 적립하고 오른쪽 상단에 개수를 표시한다. 상점 개방·상품 추가는 후속 작업이다.
- **Chosen interpretation**: 진짜 간식 획득 성공마다 보유 잔액에 즉시+1, 저장. 사망·체크포인트·스테이지 이동·게임 재접속/새로고침으로 잔액이 사라지지 않는다. 가짜 간식은 적립하지 않는다. 구매 또는 사용자가 선택한 기존 진행 초기화에서만 잔액이 줄어든다.
- **Single balance**: 기존 `ProgressState.bankedCoins:number`(기본0, 음이 아닌 정수)를 향후 상점과 HUD가 공유하는 보유 잔액으로 재사용한다. 새 통화 필드나 저장 버전을 만들지 않고 기존 저장 잔액을 승계한다. `RuntimeStageState.currentStageCoins`는 시도 통계로만 유지하며 보유 잔액에 다시 더하지 않는다.
- **Collection policy**: 기존 계획의 시도별 코인 재생성은 유지한다. 같은 활성 코인에 겹친 여러 프레임은 한 번만 적립하지만, 사망/재도전으로 다시 생성된 진짜 코인을 실제로 다시 먹으면 다시 적립한다. 영구 코인ID 소진 목록이나 별도 보상 제한은 이번 요청에 추가하지 않는다.
- **HUD**: 오른쪽 상단에 `간식 코인 1,234`처럼 현재 보유 수를 표시한다. 일반맵·보스·일시정지·사망 연출·클리어 화면에서 유지하고 최초 온보딩/이름 입력 전에는 숨긴다. 기존 오른쪽 상단 하트·일시정지·초기화 버튼과 겹치지 않게 별도 줄을 사용한다. 모바일의 `.hud-stats { display:none }` 규칙 밖에 둔다.
- **Save**: 실제 획득 처리 후 `coin-changed`를 발행하며 저장기는 변경된 공유 progress를 즉시 저장한다. 저장이 불가능한 브라우저 환경에서는 기존 ProgressStore의 오류 처리를 유지하고 성공했다고 허위 안내하지 않는다.
- **Precedence**: 이번 계획 초안의 최초 클리어 은행 적립/사망 후 표시0 규칙을 대체한다. 스테이지 완료 시 중복 적립은 제거하고 HUD는 시도 통계가 아닌 보유 잔액을 표시한다.

## Supersession

이전 짧은 경로 T01의 24개 유지/큰 위험 간격, 가짜 코인 높은 배치, 색으로 구별한다는 설명은 이번 최종 규칙으로 대체한다. 이전 삼색이 결정의 12HP와 48×24 크기는 갱신한다. 코인 정산은 D08의 획득 즉시 적립·저장이 우선한다. 완료 이력과 별도 미완료 보스 배경·깃발·하트 작업은 보존한다.
