# 검증: 보스전 진입 전 체크포인트 사망 반복

## 원인과 해결

마지막 불꽃 간식(x2000)은 발동1.7초 후 사망한다. 오른쪽으로 달리면 1.33초 만에 마지막 깃발에 닿고, 진행 중인 효과의 `triggered/startedAt`이 저장됐다. 첫 사망 후 만료된 상태가 복원되어 다음 프레임마다 죽었다. 수정 전316.7ms 동안20회를 확인했다.

- `checkpointGimmickState.ts`: `toCheckpointGimmickState()`가 가짜 간식3종의 진행 중 효과를 `{ ...state, status: "escaped", startedAt: null }`로 복사한다. 현재 시도는 그대로여서 원래 사망은1회 발생한다.
- `MapGimmickSystem.ts`: 새 체크포인트를 만들 때와 기존 스냅샷을 복원할 때 위 함수를 사용한다. 가짜 간식을 먹은 기록을 유지하되 플레이어의 사망 효과를 새 생명으로 넘기지 않는다. 지형 변화·다른 기믹은 보존한다.
- `DeathSystem.ts`: `queueMicrotask(() => { this.handlingDeath = false; })`로 잠금을 현재 JavaScript 실행 구간 끝까지 유지한다. queueMicrotask는 현재 동기 호출이 끝난 뒤 실행되어 같은 업데이트의 연속 충돌과 복원 중 재진입을 막는다. 다른 맵/폐기 후 요청도 무시한다.
- `StageScene.ts`: `() => this.runtime?.getStatus() === "play"`를 전달하여 일시정지·컷신·사망 전환·클리어 중 요청을 집계하지 않는다.
- 테스트2개 파일: 일시 효과3종·구형 스냅샷·원본 불변성·영구 지형 유지 및 중복 사망·정상 재시도·다른 맵/상태/씬 종료 후 요청을 확인한다.

알아야 할 점: 재진입 방어만으로는 매 프레임 복원되는 만료 효과를 해결할 수 없다. 저장/복원 양쪽의 상태 정리가 핵심이다. 원본 live 상태를 변경하면 깃발을 밟는 순간 가짜 간식의 현재 사망까지 취소되므로 반드시 복사본을 사용한다. 모든 triggered 기믹을 정리하면 무너진 바닥 등의 저장까지 사라지므로 간식3종으로 한정한다.

## 한계와 범위 밖 사항

- 기존에 저장된 비정상 누적 수치는 정상 사망과 구별할 사건 로그가 없어 정확히 자동 복원할 수 없다. 추정 차감이나 전체 초기화는 하지 않았다.
- 실제 모바일 기기 검증은 수행하지 않았다. 추가로 발견한 범위 밖 결함은 특이사항 없음.
