# 월드1 맵 경계 이후 체크포인트 복귀 검증

## 변경과 원인

기존 씬 종료는 로컬 체크포인트를 지우고, 새 맵의 RestartController는 현재 맵 spawn으로 복귀했다. 이제 실제로 밟은 깃발만 `ProgressState.world01CheckpointStageId`에 저장하고, `getWorld01Respawn()`으로 사망과 재접속의 복귀 맵을 정한다. 일반 맵 진입/클리어 기록은 이 값을 바꾸지 않는다.

- `StageScene`: 다른 맵 복귀를 dying 상태 및 단일 전환으로 처리한다. Phaser registry에 안전한 체크포인트 스냅샷 복사본을 보존하고, 돌아온 맵에서 기믹과 좌표를 복원한다.
- `RestartController`: `onRestartElsewhere?.()`가 처리한 사망은 현재 맵 spawn으로 순간이동하지 않는다. 다른 월드/같은 맵의 기존 복귀는 유지한다.
- `CheckpointSystem.restore()`: 같은 맵의 스냅샷만 깊은 복사로 무음 복구한다. 실제 깃발 차임은 처음 밟을 때만 발생한다.
- 저장/마이그레이션/Preload: 깃발 즉시 저장, 월드1 미완료의 이어하기도 같은 위치로 복귀한다. 현재v2에 필드를 추가했고 이전 필드와 schemaVersion/key는 보존했다.

## 자동 검사

- 전체 자동 **53건 통과**(기존47건 + 신규6건).
- `npx.cmd tsc --noEmit`, `npm.cmd run lint`, `npm.cmd run build`, `npm.cmd run world01:maps:check`, `git -c core.autocrlf=false diff --check` 통과.
- 신규6건: 맵 완료와 깃발 분리, 구형 저장 보존, 잘못된/유효한 깃발 입력, 즉시 저장과 재접속, 복사본 복원과 무음 처리, 다른 맵/가짜 깃발 거절.

## 실제 Chromium

[전체 경계/저장 측정](./assets/world01-cross-map-checkpoint.json), [실제 가시 충돌 측정](./assets/world01-cross-map-collision.json), [보스 패배 후 복귀 화면](./assets/world01-cross-map-return.png).

별도 저장 컨텍스트를 사용했다. 사용자 저장은 초기화하거나 수정하지 않았다. 이동 거리를 줄이기 위해 출구/깃발 앞까지 fixture로 이동한 뒤 실제 overlap과 오른쪽 키로 경계를 통과했다. 주요 시나리오의 사망은 실제 DeathSystem 이벤트로 유발했으며, 추가 검증에서는 실제3단계 흰 가시를 걸어서 밟았다.

| 상황 | 복귀 결과 |
| :--- | :--- |
| 깃발 없이1→2단계 진입 후 사망 | 1단계 시작 x96/y512 |
| 2단계 깃발→3단계 진입 후 사망 | 2단계 깃발 x1529/y480 |
| 위 복귀 후 같은 맵에서 재차 사망 | 같은 깃발, 차임 추가0회 |
| 2단계 깃발→3→4단계, 새 깃발 이전 사망 | 2단계 깃발 x1529/y480 |
| 4단계 새 깃발→보스 패배 | 4단계 깃발 x2329/y512 |
| 2단계 깃발만 밟은 상태에서 보스 패배 | 2단계 깃발,4단계 강제 활성화 없음 |
| 깃발 없이 보스 패배 | 1단계 시작점 |
| 월드2 진입 후 사망 | 월드2 시작점, 월드1 깃발 영향 없음 |

- 각 사망당 카운트+1이며 사망한 맵에 집계. 같은 턴 중복 요청은 무시했다. 코인10과 기존 clearedStages는 유지했다.
- 실제3단계 흰 가시(`world01-stage-3-white-spike-static-1152`) 충돌로 사망 이벤트1회,2단계 깃발 복귀, 코인10/사망1 확인.
- 다음 맵에서 새로고침해도 저장된2/4단계 깃발로 복원. 깃발 미활성 상태는1단계 시작. 복원 차임0회, 실제 새 깃발 차임1회.
- 씬 간 왕복 후 저장했던 mapSnapshot과 복원 결과가 같았다.4단계 깃발에 저장한 가짜 불꽃 간식 효과는 escaped/startedAt:null로 복원되며,2.2초 이상 관찰해도 사망이 증가하지 않았다.
- 맵 끝 표본에서 발바닥 y512 유지, 일반 STAGE CLEAR/클리어 저장 문구0개. 이전 맵 복귀 후 카메라/깃발 화면 육안 확인.
- 보스 실제 마지막 공격→대화 중 코기 좌표 변화0px·첫 대사 삼색이frame2→클리어1회→월드2 진입 정상.
- 브라우저 pageerror0건. 실제 모바일 터치와 사람이 스피커로 듣는 청음은 이번 검증에 포함하지 않았다. 차임은 실제 checkpoint-reached 이벤트 횟수로 확인했다.

## 저장 호환과 알아야 할 점

- 옛 저장에는 실제 깃발 활성화 정보가 없었다. 맵 클리어만으로 밟지 않은 깃발을 활성화하지 않는다. 따라서 월드1 미완료인 옛 저장의 첫 이어하기는 월드1 시작점이고, 이후 실제 깃발을 밟으면 저장·유지된다. 기존 코인·스킬·사망·클리어 기록은 보존된다. 보스 완료 및 월드2 이후의 기존 이어하기는 유지한다.
- 세션 중에는 지형/기믹 스냅샷을 함께 유지한다. 재접속은 깃발 식별자만 복원하고 지형/기믹은 새 맵 상태로 구성한다.
- 범위 밖 발견 사항: 특이사항 없음. 이전 계획의 '1·3단계는 항상 해당 맵 시작점' 정책은 이번 월드 단위 복귀 규칙으로 대체됐다.
