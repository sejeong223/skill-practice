# 보스 전용 클리어 문구 및 최종 통합 검증

- 대상: P01/T03. `GameShell.handleEvent`의 stage-completed 저장 알림 매핑만 제거했다. 실제 영문 큰 문구는 기존 World01StageClearScene에만 있어 그 경로를 유지했다.
- 최종 코드 기준 자동47건, `npx.cmd tsc --noEmit`, `npm.cmd run lint`, `npm.cmd run build`, diff 공백 검사 통과.
- [실제 Chromium 측정](./assets/boss-only-clear-message.json): 일반1→2→3→4→보스 진입을 실제 오른쪽 키로 진행. 1~3단계는 맵 끝100px 전, 4단계는 마지막 깃발 직전x2300부터 시작했다. DOM과 활성 Phaser Text를16ms마다 함께 관찰했다.
- 일반 전환마다 완료 이벤트1회, 전용 클리어 씬 이벤트0회, 완료 문구0개. 180ms 전환 대기 중에도 각각9/9/8/7회 표본을 수집해 문구가 없음을 확인했다.
- 단계별 완료 기록 저장, 코인10 유지, 사망0, 매 전환 후 실제 새로고침으로 다음 맵 복원 확인. 보스 패배 시 사망1회·4단계 깃발x2329 복귀이며 완료 이벤트/문구0개.
- 보스 승리를 좌측/우측/공중에서 실제 J 공격으로 마무리했다. T01 코기 위치 변화0px, T02 첫 대사 frame2, 보상1개/완료1회 유지. 대화 내내 완료 문구0개, 대화 종료 후 전용 씬의 `[STAGE CLEAR!]`1개.
- 버튼 클릭/Enter/Space 각각 월드2로1회 이동하고 이후 완료 문구0개. 보스를 완료한 저장에서 새로고침하면 전용 클리어 화면으로 복원하는 기존 동작도 정상.
- [클리어 화면](./assets/boss-only-stage-clear.png), [패배 후 깃발 화면](./assets/no-clear-banner-checkpoint.png)을 육안 확인했다.
- [첫 보스 도입 대화 회귀](./assets/calico-intro-regression.json): 아직 보지 않은 도입8개 대사를 버튼 클릭으로 끝냈다. 도입 중 조작 잠금/기본 물리 활성/삼색이 대기 그림, 대화 후 조작 해제·물리 활성·HP10을 확인했다. 승리 전용 물리 정지가 도입에는 적용되지 않는다.
- 모든 브라우저 컨텍스트의 pageerror0건. 사용자 실제 저장을 변경하지 않았다. 실제 모바일 터치는 별도 검증하지 않았다.
- 알아야 할 점: stage-completed는 자동 저장/코인 처리/다음 맵 전환에 필요하므로 그대로 전달한다. 표시 문구와 완료 처리의 역할을 분리했다. 완료 효과음 정책은 변경하지 않았다.
- 요청 범위 밖에서 새로 발견한 결함: 특이사항 없음.
